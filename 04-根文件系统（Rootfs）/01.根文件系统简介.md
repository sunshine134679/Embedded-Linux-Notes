# 根文件系统简介

## 一、什么是根文件系统

- 根文件系统也叫 `Rootfs`（Root Filesystem）。在 Linux 系统中，目录最前面的 `/` 指的就是根文件系统。
- `RootFS` != `FatFs`。`RootFS` 指 Linux 启动后挂载到 `/` 的根文件系统，描述的是文件系统的用途和角色；`FatFs` 是一种用于读写 FAT 文件系统的软件实现库，本身不属于 Linux 内核。
- 根文件系统可以理解为一组 Linux 运行所必需的文件，比如命令、库、配置文件、设备节点等。
- 根文件系统本质上就是一个目录，这个目录中包含 Linux 运行所需的子目录和文件。这些内容无法都放进内核中，因此需要单独构建。

## 二、根目录结构

Linux 根目录下常见子目录如下：

| 目录 | 作用 |
| ---- | ---- |
| `/bin` | 存放系统需要的可执行文件，一般是常用命令，例如 `ls`、`mv` 等。此目录下的命令所有用户都可以使用。 |
| `/dev` | `device` 的缩写，存放设备文件。Linux 下一切皆文件，硬件设备也以文件形式存在，例如 `/dev/ttymxc0` 表示 i.MX6ULL 串口 0。 |
| `/etc` | 存放各种配置文件。Ubuntu 的 `/etc` 内容很多，嵌入式 Linux 中通常会更简洁。 |
| `/lib` | `library` 的缩写，存放 Linux 必需的库文件。这些通常是共享库，命令和用户应用程序都会使用。 |
| `/mnt` | 临时挂载目录，一般是空目录。可以创建 `/mnt/sd`、`/mnt/usb` 等子目录，用于挂载 SD 卡或 U 盘。 |
| `/proc` | proc 虚拟文件系统挂载点。系统启动后挂载到此目录，通常用于保存系统运行信息。proc 基于内存，没有实际存储设备。 |
| `/usr` | Unix Software Resource 的缩写，不是 user 的缩写。用于存放系统软件资源，通常系统安装完成后此目录占用空间较大。 |
| `/var` | 存放会变化的数据，例如日志、缓存等。 |
| `/sbin` | 存放系统管理相关可执行文件，一般只有管理员使用。 |
| `/sys` | sysfs 文件系统挂载点。sysfs 类似 proc，也是基于 RAM 的特殊文件系统，用于向用户提供内核设备模型等信息。 |
| `/opt` | 可选文件和软件存放目录，由用户决定放置哪些软件或文件。 |

## 三、设备文件示例

以 i.MX6ULL 串口 0 为例：

```text
/dev/ttymxc0
```

如果要通过串口 0 发送或接收数据，本质上就是读写 `/dev/ttymxc0` 这个设备文件。

## 四、构建根文件系统的核心任务

构建根文件系统，就是创建上述这些目录，并放入 Linux 运行所需的文件，例如：

- 基本命令。
- 共享库。
- 配置文件。
- 设备文件。
- 启动脚本。
- 挂载点目录。
