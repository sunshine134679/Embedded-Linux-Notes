# ASM基础

> 个人补充笔记

## 一、什么是 ASM

`ASM` 通常指汇编语言。汇编语言比 C 语言更接近 CPU 指令，常用于启动代码、异常向量、寄存器配置、栈初始化和少量对性能或硬件状态要求很高的代码。

> 本文默认讨论 i.MX6ULL / Cortex-A7 常用的 AArch32，也就是 32 位 ARM 汇编场景。

在 i.MX6ULL / Cortex-A7 裸机开发中，汇编常见用途：

- 设置处理器工作模式。
- 设置 `SP` 栈指针。
- 关闭或打开 Cache、MMU。
- 设置中断向量表。
- 跳转到 C 语言入口函数。
- 读写协处理器寄存器。

## 二、ARM 常用寄存器

| 寄存器 | 说明 |
| ---- | ---- |
| `r0` ~ `r3` | 参数 / 返回值 / 临时寄存器 |
| `r4` ~ `r8` | 通用寄存器，按 AAPCS 约定通常由被调用函数负责保护 |
| `r9` | 平台相关寄存器，具体用途由平台 ABI 规定 |
| `r10` ~ `r11` | 通用寄存器，按 AAPCS 约定通常由被调用函数负责保护；`r11` 也常作帧指针 |
| `r12` / `ip` | 临时寄存器，链接器也可能使用 |
| `r13` / `sp` | 栈指针 |
| `r14` / `lr` | 链接寄存器，常保存函数返回地址 |
| `r15` / `pc` | 程序计数器，保存当前执行位置 |
| `cpsr` | 当前程序状态寄存器 |
| `spsr` | 保存程序状态寄存器，异常模式下使用 |

函数调用时，`r0` ~ `r3` 常用于传递前几个参数。32 位返回值通常放在 `r0`，64 位返回值通常放在 `r0-r1`。

## 三、常用数据传送指令

### 3.1 `mov`

把立即数或寄存器值移动到目标寄存器。

```asm
mov r0, #1
mov r1, r0
```

### 3.2 `ldr`

从内存读取数据，或加载一个立即地址。

`ldr r0, =地址` 是常见伪指令写法，汇编器可能把它转换成立即数加载，或从 literal pool 取值。

```asm
ldr r0, =0x020c4068
ldr r1, [r0]
```

### 3.3 `str`

把寄存器中的值写入内存。

```asm
ldr r0, =0x020c4068
ldr r1, =0xffffffff
str r1, [r0]
```

## 四、常用跳转指令

| 指令 | 说明 |
| ---- | ---- |
| `b` | 普通跳转，不保存返回地址 |
| `bl` | 带链接跳转，会把返回地址保存到 `lr` |
| `bx` | 跳转到寄存器保存的地址，常见写法是 `bx lr` |

示例：

```asm
b reset
bl main
bx lr
```

易错点：

- `b` 不会更新 `lr`。
- `bl` 才会保存返回地址。
- `bx lr` 常用于函数返回。
- `bx` 会根据目标地址最低位决定 ARM / Thumb 状态；最低位为 `0` 表示 ARM 状态，最低位为 `1` 表示 Thumb 状态。

## 五、常用算术和逻辑指令

| 指令 | 作用 |
| ---- | ---- |
| `add` | 加法 |
| `sub` | 减法 |
| `and` | 按位与 |
| `orr` | 按位或 |
| `bic` | 位清除，相当于 `A & ~B` |
| `cmp` | 比较，影响条件标志位 |

示例：

```asm
add r0, r1, r2
sub r0, r0, #1
orr r0, r0, #(1 << 3)
bic r0, r0, #(1 << 2)
cmp r0, #0
```

## 六、条件执行和条件跳转

AArch32 中的条件后缀很常见。A32 状态下大多数指令可以条件执行；Thumb / Thumb-2 中条件执行能力更受限制，常配合条件分支或 `IT` 块使用。

| 后缀 | 含义 |
| ---- | ---- |
| `eq` | 相等 |
| `ne` | 不相等 |
| `gt` | 有符号大于 |
| `lt` | 有符号小于 |
| `ge` | 有符号大于等于 |
| `le` | 有符号小于等于 |
| `hi` | 无符号大于 |
| `lo` | 无符号小于 |

示例：

```asm
cmp r0, #0
beq is_zero
bne not_zero
```

## 七、栈和函数调用

ARM 中 `sp` 指向栈。Cortex-A7 常见栈增长方向是向下增长，也就是地址从高地址向低地址移动。

按 AAPCS 约定，AArch32 在对外可见的函数调用边界上，`sp` 需要保持 8 字节对齐。写汇编调用 C 函数前要特别注意这一点。

普通函数保存被调用者需要保护的寄存器示例：

```asm
push {r4, lr}
```

恢复现场示例：

```asm
pop {r4, lr}
```

函数返回：

```asm
bx lr
```

如果函数入口保存了 `lr`，也常见直接恢复到 `pc`：

```asm
pop {r4, pc}
```

如果是在中断或临时保存现场中，也可能保存 `r0-r3` 这类调用者临时寄存器。但普通函数返回值通常放在 `r0`，不要在返回前无脑恢复 `r0`，否则可能覆盖返回值。

注意：例如 `push {r0-r3, lr}` 一共压栈 5 个寄存器，也就是 20 字节。如果后续还要调用 C 函数，需要额外确认 `sp` 是否仍满足 8 字节对齐。

## 八、读写状态寄存器

读 `cpsr`：

```asm
mrs r0, cpsr
```

写 `cpsr`：

```asm
msr cpsr_c, r0
```

在裸机启动代码中，常通过修改 `cpsr` 的控制字段设置处理器模式和中断状态。写 `cpsr` 属于特权操作，必须在允许的处理器模式下执行。

## 九、读写 CP15 协处理器

CP15 常用于控制 MMU、Cache、中断向量表等 Cortex-A 处理器系统功能。读写 CP15 通常也需要特权模式。

读 CP15：

```asm
mrc p15, 0, r0, c1, c0, 0
```

写 CP15：

```asm
mcr p15, 0, r0, c1, c0, 0
```

示例中的 `c1, c0, 0` 对应系统控制寄存器 `SCTLR`。关闭 MMU、Cache 时，通常会读出 `SCTLR`，清除对应位后再写回。

## 十、最小启动流程理解

裸机启动代码常见流程：

1. 设置异常向量表。
2. 设置处理器模式。
3. 关闭或配置 Cache、MMU。
4. 初始化必要硬件，例如时钟、DDR 等。对 i.MX6ULL 来说，DDR 初始化常由镜像头中的 DCD 数据配合 Boot ROM 完成。
5. 设置 `sp` 栈指针。
6. 清除 BSS 段。
7. 跳转到 C 语言入口函数 `main`。

示意代码：

```asm
reset:
	/* 设置 sp */
	ldr sp, =0x80200000

	/* 跳转到 C 入口 */
	bl main

loop:
	b loop
```
